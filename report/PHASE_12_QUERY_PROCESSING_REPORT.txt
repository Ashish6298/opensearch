1. EXECUTIVE SUMMARY & OBJECTIVES ACHIEVED
--------------------------------------------------------------------------------
Phase 12 launches Milestone 4: Query & Ranking by implementing a robust, safe,
and deterministic query processing engine in `@opensearch/ranking`.

It turns raw, potentially malformed or adversarial user query text into structured,
safe `ParsedQuery` representations ready for downstream candidate retrieval and
BM25 relevance scoring.

Key achievements:
- Query Input Validation & Type Safety: Safely handles null, undefined, boolean,
  numerical, and object inputs without throwing runtime exceptions.
- Length Limits & Boundary Clamping: Enforces `SEARCH_LIMITS.MAX_QUERY_LENGTH = 200`
  characters and token limits (min 1, max 64 characters), setting `isClamped: true`
  when clamping occurs.
- Text Normalization & Unicode Support: Implements Unicode canonical NFC normalization,
  case folding, accent/diacritic stripping ('crème brûlée' -> 'creme brulee'),
  and safely converts control characters/null bytes into clean term separators.
- Multilingual Script Support: Supports Cyrillic, CJK, Arabic, and other non-Latin
  scripts cleanly without character corruption.
- Quoted Exact Phrase Extraction: Parses double (`"phrase"`) and single (`'phrase'`)
  quoted exact expressions, preserving both the phrase string and tokenized phrase terms.
- Negation Handling: Extracts negated terms with minus (`-term`) and keyword (`NOT term`)
  syntax into `negatedTerms` while filtering them out of positive search terms.
- Empty & Malformed Query Handling: Guarantees that empty, whitespace-only, and
  punctuation-only queries return valid, empty `ParsedQuery` objects with `isEmpty: true`.
- Zero Regressions: All 275 unit tests and all 12 phase verification scripts pass with
  zero failures.

2. COMPONENT ARCHITECTURE & IMPLEMENTATION DETAILS
--------------------------------------------------------------------------------
Phase 12 added the following modules in `packages/ranking/src/query/`:

1. `query-types.ts`
   - `ParsedPhrase`: Contains `rawPhrase` string and constituent `terms[]`.
   - `ParsedQuery`: Structured query payload with `rawQuery`, `normalizedQuery`,
     `terms[]`, `uniqueTerms[]`, `phrases[]`, `negatedTerms[]`, `isEmpty`,
     `isClamped`, and `termCount`.
   - `QueryParserOptions`: Configurable constraints for query length, token length,
     stop-word removal, accent folding, and phrase/negation feature flags.
   - `QueryParser`: Interface defining `parse()`, `normalize()`, and `tokenize()`.

2. `query-normalizer.ts`
   - `normalizeQueryText()`: Strips control characters, normalizes Unicode NFC,
     folds accents/diacritics via `foldDiacritics()`, lowercases text, and normalizes
     whitespace.
   - `foldDiacritics()`: Strips Unicode combining marks (`\u0300-\u036f`).

3. `query-parser.ts` (`DefaultQueryParser`)
   - Implements `QueryParser`.
   - Performs input validation, boundary clamping, phrase extraction, tokenization,
     and negation extraction.
   - `createQueryParser()` factory for standard instantiation.

4. `index.ts` (Package root exports)
   - Exports all query processing types, utilities, and `DefaultQueryParser` / `createQueryParser`.
