2. TASKS ACCOMPLISHED & ARCHITECTURAL HIGHLIGHTS
------------------------------------------------
[x] Safe Search Capabilities & Policy Matrix:
    - Defined `SafeSearchLevel` enum ('strict' | 'moderate' | 'off') in `@opensearch/ranking`.
    - Mapped provider-specific capabilities:
      * Wikipedia / Wikimedia Commons: native filtering unsupported; local filtering applied.
      * Hacker News: native filtering unsupported; local filtering applied.
      * Mock Provider: native filtering simulated when upstream parameter is passed.
    - Exported honest disclosures (`getSafeSearchDisclosure`) explaining what Safe Search
      covers and what upstream APIs do not natively filter.

[x] High-Precision Local Explicit Content Filter:
    - Implemented `filterSafeSearchResults()` evaluating URLs, hostnames, titles, snippets,
      and metadata against curated explicit domain and keyword registries.
    - Supported strict, moderate, and off filtering tiers:
      * 'strict': filters explicit adult terms, offensive domains, and adult multimedia.
      * 'moderate': filters high-confidence adult/explicit terms while preserving educational
        and technical articles.
      * 'off': passes all results unfiltered without restriction.

[x] API Layer Integration & Metadata Reflection:
    - `fetchExternalWebResults` in `apps/api/src/external-search.ts` accepts `safeSearch`
      parameter and forwards `options.safeSearch` to all supporting search providers.
    - `/api/v1/search` endpoint extracts `safeSearch` query parameter (defaulting to
      'moderate') and applies `filterSafeSearchResults()` across combined local and external hits.
    - Returns `meta.safeSearch` payload:
      {
        level: 'strict' | 'moderate' | 'off',
        providerSupport: { wikimedia: false, hackerNews: false },
        localFilteringApplied: boolean,
        resultsFilteredCount: number,
        disclosure: string
      }

[x] User Interface Controls & Honest Transparency:
    - Injected Safe Search dropdown in the Settings modal (`#setting-safe-search-select`)
      with options:
      * Strict (Filter adult content & images)
      * Moderate (Default - Filter explicit results)
      * Off (Do not filter results)
    - Honest Disclosure Banner in UI explaining that local filtering is actively applied
      to all queries, but upstream public APIs (Wikimedia/HN) lack native server-side safe-search.
    - Query Dispatches append `&safeSearch=<level>` dynamically.
    - Results summary bar indicates filtered count when adult results are filtered out.

[x] Zero-Tracking Preference Persistence:
    - Stored strictly in browser `localStorage` under `opensearch_safe_search`.
    - No cookies, UUIDs, or server-side telemetry are created or transmitted.
    - Reset Preferences button predictably resets Safe Search back to default 'moderate'
      without deleting or corrupting local index databases.
