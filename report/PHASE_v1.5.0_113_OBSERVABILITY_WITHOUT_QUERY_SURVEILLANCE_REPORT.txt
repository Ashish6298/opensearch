1. EXECUTIVE SUMMARY & OBJECTIVES
--------------------------------------------------------------------------------
Phase 113 successfully delivers privacy-conscious observability and telemetry across
OpenSearch, completing Milestone 38 (Security and Operational Resilience):

- Operational Metrics Catalog:
  * Latency: HTTP request duration (`opensearch_http_request_duration_seconds`),
    internal search pipeline duration (`opensearch_search_pipeline_duration_seconds`),
    and upstream search provider latency (`opensearch_provider_request_duration_seconds`).
  * Provider Health: Total outbound provider requests (`opensearch_provider_requests_total`)
    and circuit breaker states (`opensearch_provider_circuit_breaker_state`: 0=closed,
    1=half-open, 2=open).
  * Result Counts: Client result count histogram (`opensearch_search_results_count`)
    binned into buckets [0, 1, 5, 10, 20, 50, 100].
  * Index Status: Total indexed documents (`opensearch_index_documents_total`), total
    unique terms (`opensearch_index_terms_total`), and index segments (`opensearch_index_segments_total`).
  * Queue Depth: Asynchronous queue depth gauge (`opensearch_queue_depth`) tracking
    pending background items (crawl queue, feedback review queue).
  * Errors: Standardized error code telemetry (`opensearch_errors_total` with codes
    `RATE_LIMITED`, `NOT_FOUND`, `VALIDATION_ERROR`, `UNAUTHORIZED`, `SERVICE_UNAVAILABLE`, `INTERNAL_ERROR`).
  * System Footprint: Node.js process uptime (`opensearch_process_uptime_seconds`) and
    V8 memory utilization (`opensearch_memory_heap_used_bytes`, `heap_total`, `rss`).

- Zero Query Surveillance Guarantee:
  * Raw search queries (`q`, `query`), search terms, and full query-bearing URLs are
    strictly prohibited from appearing as metric labels or names.
  * User identifiers, account IDs, session cookies, browser fingerprints, and client IPs
    are forbidden from metric dimensions.

- Low-Cardinality Label Enforcers:
  * Strict label key whitelist (`validateMetricLabels`): Allowed keys are bounded to
    `['method', 'path', 'status', 'status_family', 'provider', 'queue', 'mode', 'code', 'error_type', 'tier', 'le', 'quantile', 'format']`.
  * Dynamic Route Normalization (`normalizeRoutePath`): Parameterized endpoints
    (e.g., `/api/v1/lenses/:id`, `/api/v1/feedback/review/:id`) are collapsed into
    static templates, while unknown paths map to `/other`, preventing label explosion attacks.

- URL & Credential Redaction:
  * `redactSensitiveUrl`: Sanitizes query parameters (`q`, `query`, `search`, `token`,
    `key`, `secret`, `password`, `auth`, `apikey`) and HTTP basic auth credentials.
  * `stripQueryParams`: Strips query strings entirely when extracting route paths.

- Prometheus Text & JSON Snapshot Exposition:
  * Standard Prometheus exposition endpoint at `GET /metrics` (`Content-Type: text/plain; version=0.0.4; charset=utf-8`).
  * Programmatic JSON snapshot support when requested with `Accept: application/json`.

- Data Retention & Privacy Review:
  * Documented in `docs/observability-and-retention.md`.
  * In-memory metrics are strictly transient for process lifetime.
  * Operational logs never persist user search queries or client IP addresses.
