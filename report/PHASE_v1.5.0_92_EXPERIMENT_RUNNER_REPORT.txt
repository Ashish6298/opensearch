1. EXECUTIVE SUMMARY
--------------------
Phase 92 implements the offline ranking Experiment Runner and CLI evaluation
framework for OpenSearch (`@opensearch/ranking` & `@opensearch/cli`), expanding
Milestone 32 ("Search Quality Lab").

Key Accomplishments:
1. CLI Experiment Evaluation Command (`opensearch experiment` / `opensearch eval`):
   - Added CLI commands to evaluate fixed query sets against designated index and
     ranking configurations directly from the terminal.
   - Flexible CLI flags:
     * `--dataset <ci|full>`: select between CI (fast) and Full local evaluation sets.
     * `--split <tuning|held_out|all>`: select tuning split, held-out test split, or all.
     * `-k, --k <num>`: ranking cutoff depth (default: 10).
     * `--k1 <val>`, `--b <val>`, `--pagerank-weight <val>`: candidate parameter overrides.
     * `--sweep`: execute parameter grid sweep across BM25 & PageRank weights.
     * `--out-json <path>`: export machine-readable JSON report.
     * `--out-md <path>`: export formatted Markdown summary report.
     * `--json`: stream JSON report to stdout for shell pipeline scripting.
2. Full Metadata & Reproducibility Record:
   - Every experiment run records:
     * `experimentId`: unique execution identifier.
     * `timestamp`: ISO timestamp.
     * `runtimeMs`: runtime in milliseconds.
     * `indexVersion`: active index schema and build version.
     * `datasetName` & `datasetVersion`: dataset metadata.
     * `datasetSplit`: partition used ('tuning', 'held_out', 'all').
     * `queryCount`: number of evaluated queries.
     * `rankingConfig`: snapshot of baseline and candidate parameter dictionaries.
     * `metricOptions`: ranking cutoff $k$, gain method, unjudged policies.
     * `productionSafeguard`: anti-auto-tuning policy.
   - Experiments are 100% reproducible from their recorded JSON configuration blocks.
3. Baseline vs. Candidate Ranking Comparison:
   - Side-by-side metric comparison table:
     * nDCG@k, MRR, MAP, Precision@k, Recall@k.
     * Exact absolute delta ($\Delta$) and percentage relative change ($\%\Delta$).
   - Query-level Win / Loss / Tie analysis:
     * Tracks individual query wins, ties, and losses.
     * Win/Loss/Tie query ID sets recorded for failure analysis.
   - Semantic Category Breakdowns:
     * Per-category delta comparisons across everyday, education, programming,
       research, and ambiguous categories.
   - Improvement Evidence Verification:
     * Claims improvement ONLY when statistically verified ($\Delta$ nDCG > 0.005 and
       Wins >= Losses).
     * No metric improvement is claimed without output evidence.
4. Controlled Parameter Grid Sweeps (`runParameterSweep`):
   - Supports multi-dimensional Cartesian sweeps over BM25 $k_1$, $b$, $titleBoost$,
     and PageRank weights/transforms.
   - Evaluates all candidates deterministically against identical datasets.
   - Ranks configurations descending by mean nDCG and MRR, identifying Rank 1 best config.
5. Strict Production Auto-Tuning Safeguard:
   - "Do not automatically tune production ranking based on unreviewed feedback."
   - The engine strictly disallows automated modification of production configurations.
   - Every report and CLI output explicitly injects the mandatory safeguard banner:
     "Automated production tuning is strictly prohibited. Any ranking adjustments
      require manual review and pull request approval."

All 836 automated tests across 78 test suites in the OpenSearch monorepo pass cleanly
with a 100% pass rate. TypeScript composite compilation (`tsc -b`) succeeds with zero errors.

Status: COMPLETED.
Readiness for Next Phase: READY for Phase 93 (Ranking regression checks).
