1. EXECUTIVE SUMMARY
--------------------
Phase 83 implements and enforces strict, non-bypassable Local-only search mode
across both the backend query planner / API routing layers and the user interface.

When Local-only mode is enabled:
1. The search engine queries exclusively the local inverted index, local documents,
   and executes local in-memory computations.
2. External web search providers (Wikimedia OpenSearch, Wikimedia Commons, Hacker News)
   are strictly disabled and cannot be called under any condition.
3. The query planner enforces this invariant on the server backend—precluding any
   silent fallback to third-party endpoints even if local results are zero.
4. An honest limited-results message and clear actionable empty state explain the
   limitations of the mode with a one-click path to switch to global web search.
5. The UI prominently displays a visible Local-only control before search submission
   and transparently explains that while a remote hosted server receives queries
   submitted to its own endpoint over HTTPS, zero external providers are contacted.

All 719 automated tests across 67 test suites in the OpenSearch monorepo pass cleanly
with a 100% pass rate. TypeScript composite compilation (`tsc -b`) and asset bundling
succeed with zero warnings or errors.

Status: COMPLETED.
Readiness for Next Phase (Phase 84 — Privacy Receipt schema): READY.


2. TASKS ACCOMPLISHED & ARCHITECTURAL HIGHLIGHTS
------------------------------------------------
[x] Visible Local-Only Control on Main Interface:
    - Added `#local-only-checkbox` in `.search-mode-controls` directly on the primary
      search page above the quick topics and below the search input.
    - Synchronized bidirectionally with the Settings modal toggle `#setting-local-only-toggle`.
    - Persisted non-sensitively in browser `localStorage` under `opensearch_local_only`.

[x] Strict Backend Query Planner Enforcement (`@opensearch/api`):
    - Evaluates `localOnly=true` or `mode=local` on `/api/v1/search`.
    - Disables all provider invocations (`canFetchExternal = !isLocalOnly && ...`).
    - Guarantees zero external provider dispatches even if local hits are 0.
    - Injected `providerRegistry` into `ApiServerOptions` and `SearchServices` to enable
      deterministic testing with mock providers.

[x] Honest Limited-Results & Empty-State Messaging:
    - Returns `meta.localOnly: true` and `meta.limitedResultsNotice` when local coverage
      is insufficient:
      * 0 hits: "Local-only mode active: No matching documents found in the local index. External search providers are disabled for privacy."
      * Limited hits: "Local-only mode active: Displaying N local document(s). External search providers are disabled for privacy."
    - UI renders `#local-only-notice-banner` above search results and `#empty-local-only-action`
      in empty states.
    - Includes one-click action buttons (`#disable-local-only-btn` and `#empty-disable-local-only-btn`)
      allowing immediate transition to web search.

[x] Hosted Service Transparency Disclosure:
    - Clearly explains in both the search controls and Settings modal:
      "If accessing OpenSearch on a remote hosted server, the host server receives the query
      submitted to its endpoint over HTTPS. Local-only mode guarantees the host will not contact
      external search engines. For absolute zero-network privacy, run OpenSearch on your local device."

[x] Local Computation Preservation:
    - In Local-only mode, local mathematical evaluations, unit conversions, timezone lookups,
      and developer cheatsheets remain fully functional as zero-egress in-memory computations.
