## OVERVIEW

Phase 3 establishes a clean, persistent, replaceable storage foundation for
crawled documents and search metadata. The implementation follows an
adapter-pattern architecture: all storage contracts are defined as TypeScript
interfaces, and the first concrete backend is a zero-dependency JSON file store.
Future phases (crawler, indexer, search) depend only on the interfaces, not on
the JSON backend, making the storage layer swappable without touching any other
package.

All work is scoped to the @opensearch/storage package. No other packages were
modified except package.json (added verify:phase3 script).

## DESIGN DECISIONS

1. JSON file backend (not SQLite)
   The project requires zero external dependencies at V1.0.0 and the storage
   layer must be demonstrably replaceable. A pure JSON store with atomic writes
   is durable, zero-config, and requires no native binaries. A future phase can
   swap to SQLite (better-sqlite3) or PostgreSQL by implementing StorageAdapter.

2. Atomic writes (tmp+rename)
   `fs.writeFileSync(tmpPath) → fs.renameSync(tmpPath, filePath)` is atomic on
   most OS/filesystem combinations. If the process crashes mid-write, the old
   file is intact and the .tmp file is orphaned (harmless).

3. Adapter pattern — strict interface separation
   packages/storage/src/repositories.ts defines pure TypeScript interfaces.
   The JsonStorageAdapter lives behind those interfaces. No other package imports
   the concrete adapter class directly; all usage goes through createStorageAdapter()
   and the StorageAdapter interface.

4. In-memory secondary indexes
   URL→DocumentId and URLHash→DocumentId maps are rebuilt from the JSON file
   on initialize(). This gives O(1) lookup-by-url and lookup-by-hash without
   needing secondary index files. Rebuilding on start keeps state consistent
   even if the process crashed between a write and an index update.

5. Create/Update input types separated from full records
   CreateDocumentInput omits system-managed fields (id, crawledAt, updatedAt,
   indexStatus). UpdateDocumentInput makes all non-identifier fields optional.
   This enforces correct usage at the TypeScript level.

6. Validation at storage boundary, not deep inside
   All validation happens in validation.ts before any file I/O. If an invalid
   input reaches the adapter, it throws a ValidationError (not a StorageError).
   This makes error handling predictable for callers.
