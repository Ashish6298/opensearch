1. EXECUTIVE SUMMARY & OBJECTIVES
--------------------------------------------------------------------------------
Phase 112 implements enterprise-grade health checks, readiness probes, honest system
status reporting, and coordinated graceful shutdown lifecycle management across OpenSearch:

- Health vs. Readiness Endpoints with Distinct Semantics:
  * Liveness checks: `GET /health` and `GET /healthz`.
    Reports process vitality, uptime, memory, version, and component status. Returns HTTP 200
    even when in-flight requests are draining, ensuring orchestrators (Kubernetes, Docker Swarm,
    systemd) do not prematurely SIGKILL the draining process before work completes.
  * Readiness checks: `GET /ready` and `GET /readyz`.
    Determines whether the server can actively accept and process queries. Returns HTTP 200
    only when storage/index is online and server lifecycle state is 'ready'. Immediately
    returns HTTP 503 Service Unavailable when the index is not ready or when graceful shutdown
    has commenced (`shutting_down`), prompting ingress reverse proxies (Nginx, Envoy, ALB)
    to cease routing new external traffic to this node.

- Honest System Status & Partial Degradation Reporting:
  * System status: `GET /api/v1/status`.
  * Honestly exposes partial degradation: overall status is `'healthy'` when all components
    are operational, and `'degraded'` when one or more external search providers are tripped
    or storage is degraded.
  * Reports individual search provider availability and circuit breaker states (closed, open,
    half-open) without leaking queries, parameters, or private upstream tokens.
  * Reports index document counts, segment counts, and storage readiness without leaking
    sensitive internal file paths, IP addresses, credentials, or stack traces.

- Graceful Shutdown & Work Draining Lifecycle:
  * Tracks server lifecycle states: `initializing` -> `ready` -> `shutting_down` -> `stopped`.
  * Signals: Registers clean `SIGTERM` and `SIGINT` handlers (via `enableGracefulShutdown()`),
    preventing duplicate signal handling and unhandled termination exceptions.
  * Stop accepting new work: During shutdown, all new incoming requests are immediately
    rejected with HTTP 503 `SERVER_SHUTTING_DOWN`, `Connection: close`, and `Retry-After: 5`.
  * Work draining: In-flight requests are tracked with `activeRequestsCount` and bounded sockets
    in `activeSockets`. Draining awaits in-flight completions up to a configurable grace period
    (default 5000ms).
  * State flushing: Automatically flushes persistent state stores (e.g. rate limiters) and
    purges memory caches (query cache) before terminating socket listeners.
