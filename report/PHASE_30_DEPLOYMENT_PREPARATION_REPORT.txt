--------------------------------------------------------------------------------
2. ARCHITECTURAL & IMPLEMENTATION DETAILS
--------------------------------------------------------------------------------
A. Production Environment Adaptation:
   - Dynamic binding to platform-injected `PORT` and `HOST` variables (PaaS compatibility).
   - In production (`NODE_ENV=production`), defaults host binding to `0.0.0.0`.
   - Dynamic `API_URL` and `VITE_API_URL` resolution for flexible frontend-backend decoupled hosting.
   - Enforced production validation requirements (e.g. `CORS_ORIGIN`).

B. Build & Packaging Pipeline:
   - Updated root `package.json` scripts: `start`, `start:api`, `start:web`.
   - Direct execution support for standalone service invocations (`node ./dist/index.js`).
   - Clean, reproducible builds via `npm run build` across all workspace packages.

C. Health Endpoint & Monitoring:
   - `GET /health` on Search API reports overall status, uptime seconds, memory usage in MB, environment, total indexed documents, and individual subcomponent states (index, rateLimiter, queryCache).
   - `GET /health` on Web server reports application health and status.
   - Graceful state degradation if memory exceeds 512MB or if the index is empty.

D. Index Deployment & Update Strategy:
   - Documented in `docs/DEPLOYMENT.md`.
   - Versioned index directory builds (`<indexDir>/builds/<build-id>`) with atomic activation via `storage.indexMetadata` ensure zero-downtime updates in live environments.
