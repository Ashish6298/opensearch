1. PHASE OVERVIEW & OBJECTIVE
--------------------------------------------------------------------------------
Phase Name: Phase 2 — Configuration & Shared Infrastructure
Milestone:  Milestone 1 — Project Foundation
Objective:  Build a centralized, type-safe, maintainable configuration and
            shared infrastructure layer on top of the Phase 1 foundation.
            Eliminate scattered `process.env` lookups by establishing a robust
            environment parsing and validation system with distinct development
            and production behaviors; implement a structured logging foundation
            with levels, contextual metadata, and secret sanitization; establish
            common error types and an error-handling foundation with safe client
            serialization; provide common reusable utilities; and centralize
            application constants, timeouts, and operational limits across the
            workspace.

Scope Constraints Strictly Respected:
- NO crawler fetching, URL queue, or scheduling implemented.
- NO robots.txt parsing or politeness orchestration implemented.
- NO HTML parsing or content extraction implemented.
- NO indexing, inverted index, or document processing implemented.
- NO search retrieval or BM25 ranking implemented.
- NO public search endpoints or UI redesign implemented.
- NO speculative utilities or circular package dependencies introduced.


2. ARCHITECTURE & IMPLEMENTATION SUMMARY
--------------------------------------------------------------------------------
All Phase 2 shared infrastructure is cleanly centralized in `@opensearch/shared`
and made accessible across workspaces:

A. Centralized Configuration System (`packages/shared/src/config/`):
   - `types.ts`: Strictly typed contracts for `AppConfig`, `ServerConfig`,
     `StorageConfig`, `CrawlerConfig`, `SearchConfig`, `LoggingConfig`, `ApiConfig`,
     and `WebConfig`.
   - `env.ts`: Safe environment reader utilities (`readString`, `readInt`,
     `readBoolean`, `readEnum`) providing boundary checking, integer parsing,
     range constraints, and safe validation errors.
   - `index.ts`: `loadConfig(sourceEnv)` reads, validates, applies sensible
     defaults, checks production constraints, and freezes the resulting object
     via `Object.freeze()`. Also provides `sanitizeConfigForLogging()` for safe
     diagnostic logging.

B. Development vs. Production Separation:
   - Development mode: Permissive defaults for rapid local development (ports
     3000/5173, pretty logging at DEBUG level, local CORS origins allowed).
   - Production mode: Strict validation (enforces explicit `CORS_ORIGIN`,
     defaults logging to INFO in structured JSON format).
   - Test mode: Silent/targeted log controls and lightweight isolation.

C. Shared Logging Foundation (`packages/shared/src/logger/`):
   - `createLogger(moduleName, options)`: Creates contextual, namespaced loggers.
   - Log levels: `debug`, `info`, `warn`, `error`, `silent` with strict priority
     filtering.
   - Formats: Human-readable timestamped output (`pretty`) for dev and structured
     JSON (`json`) with ISO timestamps for production.
   - Privacy & Secret Sanitization: Integrated `redactSensitiveData()` recursively
     redacts passwords, tokens, API keys, cookies, credentials, and secrets.
     Privacy-first compliance prevents logging full user search queries.

D. Common Error Foundation (`packages/shared/src/errors/`):
   - `OpenSearchError`: Extends native `Error`, contains `code`, `statusCode`,
     `category`, `context`, `timestamp`, and clean `toJSON()` serialization.
   - Domain Subclasses: `ConfigError`, `ValidationError`, `NotFoundError`,
     `ConflictError`, `TimeoutError`, `SecurityError`, `StorageError`,
     `ServiceUnavailableError`.
   - Client Safety: `toSafeErrorResponse(error)` strips internal stack traces
     and sensitive server context for external API responses while retaining
     machine-readable error codes and status codes.

E. Common Utility Layer (`packages/shared/src/utils/`):
   - `normalizeWhitespace(input)`: Safe whitespace collapsing and trimming.
   - `clamp(val, min, max)`: Safe numeric boundary enforcement.
   - `safeJsonParse(raw, fallback)`: Crash-proof JSON deserialization.
   - `isNonEmptyString(val)`: Safe TypeScript type guard.
   - `sanitizeUrl(rawUrl)`: URL format validation and HTTP/HTTPS protocol guard.
   - `maskSecret(str)`: Safe partial string masking for debugging.
   - `deepClone(obj)`: Safe object deep cloning.

F. Central Constants & Operational Limits (`packages/shared/src/constants.ts`):
   - Project metadata: `PROJECT_NAME`, `PROJECT_VERSION`.
   - Environments: `development`, `production`, `test`.
   - Network coordinates: `DEFAULT_HOST`, `DEFAULT_API_PORT`, `DEFAULT_WEB_PORT`.
   - Storage defaults: `DEFAULT_STORAGE_DIR`, `DEFAULT_INDEX_DIR`, `DEFAULT_CRAWLER_DATA_DIR`.
   - Crawler limits: `CRAWLER_LIMITS` (timeouts, depth ceilings, politeness delays, max page sizes).
   - Search limits: `SEARCH_LIMITS` (query lengths, page sizes, search timeouts).
   - API limits: `API_LIMITS` (rate limits, request body limits).
   - HTTP status codes: Full typed map of standard status codes.

G. Application Integration:
   - Updated `apps/api/src/index.ts` to expose `createApiContext()` consuming
     `loadConfig()` and `createLogger()` from `@opensearch/shared`.

6. ISSUES ENCOUNTERED & RESOLUTIONS
--------------------------------------------------------------------------------
1. Issue: Unused import `readBoolean` in `packages/shared/src/config/index.ts`
   flagged by TypeScript compiler (`TS6133`).
   Resolution: Removed unused import.

2. Issue: `readString` provided an empty string default in production for
   `CORS_ORIGIN`, preventing the `required: isProduction` check from triggering.
   Resolution: Passed `defaultValue: isProduction ? undefined : ...` so that
   in production, absence of `CORS_ORIGIN` throws `ConfigError` as intended.

3. Issue: Prettier formatting discrepancy in newly created error and API files.
   Resolution: Ran `npm run format` and verified with `npm run format:check`.
