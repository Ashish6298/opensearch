2. IMPLEMENTED COMPONENTS & DEPLOYMENT STRATEGY
--------------------------------------------------------------------------------
1. Frontend Deployment (@opensearch/web):
   - Zero-dependency Node.js HTTP server hosting the semantic HTML shell, CSS, and JS
   - Automatic injection of runtime `VITE_API_URL` into HTML head
   - Modern defensive security headers:
     * Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
     * Content-Security-Policy
     * X-Content-Type-Options: nosniff
     * X-Frame-Options: DENY
     * Referrer-Policy: strict-origin-when-cross-origin
   - Static routes: `/` (Search Shell), `/privacy` (Privacy Policy), `/health` (Health probe), `/style.css`, `/app.js`

2. API Deployment (@opensearch/api):
   - Production HTTP API service running on dynamic host/port bindings
   - Reverse-proxy TLS awareness via `X-Forwarded-Proto` detection
   - CORS origin enforcement and OPTIONS preflight caching
   - Subsystem integration: InvertedIndex, QueryParser, CandidateRetriever, BM25 RankingEngine, ResultGenerator, LRU QueryCache

3. Production Index & Storage Deployment Strategy:
   - Automated deployment bootstrap runner: `scripts/deploy-production.mjs`
   - Zero-cost disk-backed storage adapter (`@opensearch/storage`)
   - Curated seed corpus (`CURATED_SEED_CORPUS`) covering documentation, encyclopedias, and open web
   - Deterministic index generation and atomic zero-downtime activation

4. Monitoring & Health Verification:
   - Real-time `/health` endpoint reporting overall status (`ok`, `degraded`, `error`)
   - Component readiness reporting: `index`, `rateLimiter`, `queryCache`, `memory`
   - Memory metrics tracking: `heapUsedMb`, `heapTotalMb`, `rssMb` (staying under 512MB free-tier limits)
