1. IMPLEMENTATION SUMMARY
--------------------------------------------------------------------------------
Phase 37 implements precision filtering using query syntax operators (`site:`,
`intitle:`, `exact:`, `filetype:`, `"exact phrase"`, `-term` / `NOT term`) giving developers
and researchers granular control over candidate retrieval and ranking with zero external dependencies:

1. Extended Query Lexer & Parser (@opensearch/ranking & @opensearch/indexer):
   - Defined `QueryFilter` contract in `packages/ranking/src/query/query-types.ts`:
     * `site?: string` (domain/hostname filter)
     * `intitle?: string[]` (HTML <title> tag filter)
     * `filetype?: string` (file extension filter, e.g. pdf, md, json)
     * `exact?: string[]` (exact token/phrase requirement)
   - Updated `DefaultQueryParser` in `packages/ranking/src/query/query-parser.ts`:
     * Regex operator tokenization extracting `site:<domain>`, `filetype:<ext>`, `intitle:<word>`, and `exact:<word>`.
     * Clean extraction separating structural filter constraints from free-text search terms.
     * Guaranteed non-crashing safe fallback for malformed or operator-only queries.
   - Comprehensive unit test suite in `packages/ranking/tests/query-parser.test.ts` (21/21 passed).

2. Candidate Retrieval Filtering Pipeline (@opensearch/ranking):
   - Updated `IndexCandidateRetriever` in `packages/ranking/src/retrieval/candidate-retriever.ts`:
     * Post-retrieval and pre-scoring filter pipeline enforcing operator constraints on document metadata (`docMeta.url`, `docMeta.title`).
     * Domain hierarchy matching supporting apex and subdomains (e.g. `site:github.com` matches `github.com` and `api.github.com`).
     * Title containment check strictly evaluating terms occurring in document title metadata.
     * File extension matching on URL pathnames.
     * Handled operator-only queries (e.g. `site:opensearch.dev`) by scanning document metadata without requiring positive text postings.
   - Retrieval integration tests in `packages/ranking/tests/candidate-retriever.test.ts` (13/13 passed).

3. Search API & Web Frontend Integration (@opensearch/api & @opensearch/web):
   - Updated `SearchApiResponse` schema in `apps/api/src/types.ts` to include `query.filters`.
   - Populated `filters` in `apps/api/src/routes.ts` response payload.
   - Added active filter summary token display in the terminal meta line (`apps/web/src/app.js` and `style.css`).
