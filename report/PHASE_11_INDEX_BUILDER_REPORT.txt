1. EXECUTIVE SUMMARY & OBJECTIVES ACHIEVED
--------------------------------------------------------------------------------
Phase 11 implements the robust, production-grade Index Builder and Rebuild Pipeline
in @opensearch/indexer. It connects stored crawled documents in the DocumentRepository
(Phase 3) through the Document Processing Pipeline (Phase 9) and persists them into
the structured Inverted Index (Phase 10), completing Milestone 3: Search Index.

Key achievements:
- Full Index Build: Ingests documents in configurable batches from storage, parses
  and extracts tokens with field weights, generates term dictionary and posting lists,
  and persists to disk.
- Incremental Update Capability: Detects and processes documents in PENDING or STALE
  status without requiring a full re-indexing cycle, cloning active index postings
  and merging new document terms cleanly.
- Deterministic Build Behavior: Verified that identical crawled corpora produce
  identical term dictionary structures, term frequencies, and posting offsets.
- Staging Directory Isolation & Atomic Swaps: Builds execute into isolated staging
  folders (<indexDir>/builds/<buildId>). The active index is only activated in
  storage metadata after complete validation and flush.
- Robust Corruption & Error Handling: Simulated disk I/O and batch parsing failures
  prove that broken builds do not overwrite active indices and staging data is
  purged cleanly.
- Index Version Metadata & Statistics: Integrates with IndexMetadataRecord to track
  build IDs, versions, document counts, total unique terms, duration, and status.
- Zero Regressions: All test suites from Phase 1 through Phase 11 continue to pass
  with zero errors.

2. COMPONENT ARCHITECTURE & IMPLEMENTATION DETAILS
--------------------------------------------------------------------------------
Phase 11 added the following modules in `packages/indexer/src/builder/`:

1. `builder-types.ts`
   - `IndexBuildOptions`: Configures build mode ('full' | 'incremental'), versionLabel,
     batchSize, targetDir, and force flags.
   - `IndexBuildStats`: Tracks buildId, version, mode, documentsExamined,
     documentsIndexed, documentsSkipped, termsIndexed, postingsCount, avgDocLength,
     startedAt, completedAt, durationMs, and status.
   - `IndexBuildSummary`: Summary object returned upon build completion.
   - `IndexBuilder`: Interface defining `build()`, `getActiveIndex()`,
     `getActiveMetadata()`, and `loadActiveIndex()`.

2. `index-builder.ts` (`DefaultIndexBuilder`)
   - Manages the end-to-end build lifecycle.
   - Creates a new `IndexMetadataRecord` with status 'building'.
   - Staging build directory isolation: Writes into `<indexDir>/builds/<buildId>`.
   - Incremental mode: Pre-populates the staged index with active index postings.
   - Batch document fetching from `DocumentRepository` via `storage.documents.list`
     or `findByIndexStatus`.
   - Text normalization and tokenization through `DocumentProcessor`.
   - Serializes index to disk (`index-data.json`) via `MemoryInvertedIndex.save()`.
   - Atomic metadata swap: Switches previous active index to inactive/stale and
     activates the new index build in `storage.indexMetadata`.
   - Updates document index status to `INDEX_STATUS.INDEXED` with `lastIndexedAt`
     and `indexVersion`.
   - Error handling: Catches exceptions, records failure in metadata, preserves
     active index intact, and purges staging directory.
   - `loadActiveIndex()`: Automatically locates the active index build on disk
     or triggers an initial build on first startup.

3. `builder-factory.ts`
   - Factory function `createIndexBuilder(options)` exposing standard initialization.

4. `index.ts` (Package root exports)
   - Re-exports `IndexBuilder`, `IndexBuildOptions`, `IndexBuildStats`,
     `IndexBuildSummary`, `DefaultIndexBuilder`, and `createIndexBuilder`.
