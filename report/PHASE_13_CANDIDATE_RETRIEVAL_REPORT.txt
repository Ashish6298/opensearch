1. EXECUTIVE SUMMARY & OBJECTIVES ACHIEVED
--------------------------------------------------------------------------------
Phase 13 establishes the Candidate Retrieval subsystem in `@opensearch/ranking`,
connecting the structured `ParsedQuery` (Phase 12) to the `InvertedIndex` (Phase 10)
to efficiently retrieve, filter, and merge candidate documents for downstream ranking.

Key achievements:
- Term Lookup & Posting Retrieval: Performs indexed lookups across unique positive
  query terms in the InvertedIndex dictionary.
- Candidate Merging & Aggregation: Aggregates matching terms and detailed field-level
  postings per candidate document, computing `matchedTerms`, `matchCount`, and
  `isFullMatch`.
- Boolean Combination Modes:
  - 'intersection': Strictly returns documents containing all searched terms.
  - 'union': Returns documents matching at least one search term.
  - 'adaptive' (default): Attempts intersection first and falls back to union if
    candidate yield is under threshold.
- Negation Filtering: Evaluates `negatedTerms` from Phase 12 query processing,
  purging any candidate document containing excluded terms.
- Phrase Verification: Verifies exact adjacent token positional sequences across
  document fields when quoted phrases (`"exact match"`) are specified.
- Result Limits & Diagnostics: Clamps output candidates to `maxCandidates` (default: 500)
  and tracks performance statistics (`searchedTerms`, `missingTerms`, `durationMs`).
- Safe Failure & Edge Cases: Missing terms, empty queries, or empty indices cleanly
  return safe empty results (`candidates: []`) without throwing.
- Zero Regressions: All 284 unit/integration tests and all 13 phase verification
  suites pass with zero errors.

2. COMPONENT ARCHITECTURE & IMPLEMENTATION DETAILS
--------------------------------------------------------------------------------
Phase 13 added the following modules in `packages/ranking/src/retrieval/`:

1. `retrieval-types.ts`
   - `RetrievalMode`: 'union' | 'intersection' | 'adaptive'.
   - `CandidateDocument`: Document ID, `documentMeta`, `matchedTerms`, `termPostings`,
     `matchCount`, `isFullMatch`, and `phraseMatches`.
   - `RetrievalOptions`: Configurable `mode`, `maxCandidates`, `minCandidatesForAdaptive`,
     and `applyNegationFilter`.
   - `RetrievalStats`: Diagnostics metrics including `searchedTerms`, `missingTerms`,
     `totalPostingsEvaluated`, `candidateCount`, `effectiveMode`, and `durationMs`.
   - `RetrievalResult`: Final output payload containing `candidates[]` and `stats`.
   - `CandidateRetriever`: Primary retrieval interface defining `retrieve()`.

2. `candidate-retriever.ts` (`IndexCandidateRetriever`)
   - Implements `CandidateRetriever` against an `InvertedIndex` instance.
   - Merges candidate postings and tracks full matches vs partial matches.
   - Positional sequence verification for quoted exact phrases (`verifyPhrases()`).
   - `createCandidateRetriever()` factory function.

3. `index.ts` (Package root exports)
   - Re-exports all Phase 13 retrieval types, `IndexCandidateRetriever`, and
     `createCandidateRetriever`.
