1. PHASE OVERVIEW & OBJECTIVE
--------------------------------------------------------------------------------
Phase Name: Phase 1 — Repository & Project Initialization
Milestone:  Milestone 1 — Project Foundation
Objective:  Create a clean, reproducible, maintainable initial repository
            structure for OpenSearch, an independent, public, general-purpose,
            privacy-first search engine. Establish clear frontend, backend, and
            service boundaries; configure package management and development
            tooling; establish safe environment configuration; add documentation,
            scripts, and git ignore policies; and define sensible engineering
            conventions for future phases.

Scope Constraints Strictly Respected:
- NO web crawler implemented.
- NO search ranking implemented.
- NO indexing system implemented.
- NO search API endpoints or query pipelines implemented.
- NO unnecessary UI features implemented.
- Purely architectural, repository, tooling, and boundary scaffolding.


2. ARCHITECTURE & BOUNDARIES
--------------------------------------------------------------------------------
The OpenSearch repository is structured as an npm workspaces monorepo using
TypeScript composite project references (`tsc -b`). Strict boundaries are
established to isolate concerns and prepare for subsequent phases:

- `apps/api`:
  Search API service boundary. Provides HTTP endpoints, query validation, and
  health checks (Phase 16-18 implementation). In Phase 1, basic application
  scaffolding, environment template, and initial health status exports are defined.

- `apps/web`:
  Public search frontend boundary. Clean, responsive web user interface
  (Phase 19-21 implementation). In Phase 1, basic interface scaffolding and
  environment template are defined.

- `packages/shared`:
  Centralized models, system types, error structures, constants, and shared
  utilities. All workspaces consume shared types without cyclic dependencies.

- `packages/storage`:
  Storage abstraction and persistence models for crawled documents and search
  metadata (Phase 3 implementation).

- `packages/crawler`:
  Polite, policy-aware web crawler module boundary (Phase 4-8 implementation).

- `packages/indexer`:
  Document processing, inverted index, and index build pipeline boundary
  (Phase 9-11 implementation).

- `packages/ranking`:
  Deterministic relevance ranking engine boundary (Phase 12-15 implementation).

- `scripts`:
  Automation scripts for lifecycle operations: cleaning, verification, and checks.

- `report`:
  Standardized report directory containing audit and phase verification reports.
