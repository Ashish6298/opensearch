2. ARCHITECTURAL & COMPONENT OVERVIEW
--------------------------------------------------------------------------------
A. Search Endpoint Router Handlers (`apps/api/src/routes.ts`):
   - `handleSearch`: Dual-method route handler supporting GET query parameters and POST JSON payloads.
   - Validates page (`>= 1`) and pageSize (`1 <= size <= maxPageSize`).
   - Validates query length (`<= maxQueryLength`).
   - Coordinates service pipeline: QueryParser -> CandidateRetriever -> RankingEngine -> ResultGenerator.
   - Formats unified `SearchApiResponse` schema with parsed query metadata, hit items, pagination state, and execution metrics.

B. Service Wiring & Server Integration (`apps/api/src/server.ts`):
   - `initializeSearchServices`: Automatically wires `InvertedIndex`, `QueryParser`, `CandidateRetriever`,
     `RankingEngine`, and `ResultGenerator` into the API application context.
   - Exposes `/api/v1/search` across GET and POST.

C. Response Schema (`SearchApiResponse` in `apps/api/src/types.ts`):
   - `query`: Breakdown of raw query, normalized query, positive terms, phrases, and negated terms.
   - `results`: List of `SearchResultItem` records containing titles, highlighted titles, URLs, display URLs, domains, snippets, and highlighted snippets.
   - `pagination`: Multi-page navigation state.
   - `meta`: Execution duration in ms, candidate count, total hits, and ISO timestamp.
