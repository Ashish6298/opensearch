1. ACCEPTANCE CRITERIA VERIFICATION
--------------------------------------------------------------------------------

[PASS] Criterion 1: One failed provider cannot crash the entire search experience.
       - Implemented per-provider timeouts and global search deadline (searchDeadlineMs)
         using bounded AbortControllers and Promise.race timers.
       - Complete failure isolation in ProviderRegistry.runWithConcurrency and executeSingleProvider:
         any thrown error, timeout, malformed payload, or network drop in one provider is
         caught, classified, sanitized, and isolated.
       - Healthy providers complete normally and their results are aggregated without
         interruption.

[PASS] Criterion 2: All error states are understandable.
       - Standardized ProviderErrorCode taxonomy:
         * TIMEOUT: "The search provider did not respond within the allocated time limit."
         * RATE_LIMITED: "The search provider rate limit was reached. Cooldown initiated."
         * UPSTREAM_ERROR: "The upstream provider encountered a temporary service disruption."
         * NETWORK_ERROR: "Unable to reach the search provider due to an offline or network error."
         * INVALID_RESPONSE: "The provider returned an unrecognized or corrupted data format."
         * OVERSIZED_RESPONSE: "The provider response exceeded the maximum permitted size limit."
         * CANCELLED: "The search request was cancelled."
         * CIRCUIT_OPEN: "Provider temporarily suspended to protect against upstream failure storms."
         * DISABLED: "The search provider is currently disabled."
       - Zero internal stack traces, filesystem paths, or upstream URLs are exposed in
         user-facing messages.

[PASS] Criterion 3: Cache behavior matches documented privacy rules.
       - In-memory ProviderResponseCache strictly uses deterministic query-only keys
         (providerId + normalized query + limit + categories).
       - Zero personal identifiers, client IP addresses, cookies, or tracking tokens are stored.
       - Respects provider cache policies (TTL and max size) with LRU eviction.
       - Zero disk persistence for cached queries.
