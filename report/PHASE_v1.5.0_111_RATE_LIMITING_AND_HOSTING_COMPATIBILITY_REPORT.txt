1. EXECUTIVE SUMMARY & OBJECTIVES
--------------------------------------------------------------------------------
Phase 111 delivers architectural hosting compatibility, durable storage validation,
multi-tier rate limiting, and trusted reverse proxy security across OpenSearch:

- Deployment Models & Guarantees:
  * Formalized three deployment models: `standalone` (default, single node VPS / bare metal),
    `cluster` (multi-process / multi-instance behind reverse proxy), and `serverless`
    (ephemeral tasks with external persistent mount requirements).
  * Documented multi-instance rate-limiting behavior: process-memory limits apply per-instance
    and cannot provide global guarantees alone; implemented `FileBackedRateLimitStore`
    (atomic disk sync) to share quotas across local processes without requiring Redis,
    and documented reverse-proxy / edge WAF rate limiting for distributed clusters.
  * Zero paid infrastructure invariant: the complete search, index, crawler, PageRank,
    and rate limiting architecture operates 100% on local hardware or self-hosted VPS
    without requiring third-party SaaS, paid databases, or Redis.

- Durable Index Storage vs Ephemeral Filesystems:
  * Implemented `auditStoragePersistence()`, `isEphemeralPath()`, and `verifyStorageWritable()`.
  * Detects and warns against mounting storage in ephemeral filesystems (`/tmp`, `/var/tmp`,
    `/dev/shm`, `os.tmpdir()`), providing actionable persistent volume mount instructions.
  * Emits critical data loss warnings when running production deployments on ephemeral paths.

- Route-Specific & Provider-Specific Rate Limits:
  * Route tiers:
    - Search & MCP (`/api/v1/search`, `/api/v1/mcp`): default 60 req/min.
    - Instant / Quick Answers (`/api/v1/instant-answer`): default 30 req/min.
    - Crawl & Administrative Review (`/api/v1/feedback/review`, crawler start): default 10–20 req/min.
    - Lightweight Metadata (`/api/v1/suggest`, `/health`, `/api/v1/status`, `/opensearch.xml`): default 180–300 req/min.
  * Operation Complexity Weighting:
    - Standard lexical queries: cost = 1 token.
    - Wildcard/pattern queries (`*`, `?`, `~`): cost = 2 tokens.
    - Oversized candidate limits (`limit > 50`): cost = 2 tokens.
    - Administrative operations: cost = 2 tokens.
  * Provider Rate Limiter (`ProviderRateLimiter`):
    - Proactively throttles outbound calls to external search providers (Wikimedia, etc.)
      to prevent upstream HTTP 429s and IP bans.

- Trusted Proxy Settings & IP Spoofing Prevention:
  * Implemented `resolveClientIp(req, trustProxy)`.
  * `trustProxy: false` (secure default): strictly ignores `X-Forwarded-For` and uses
    `req.socket.remoteAddress`, completely preventing client IP spoofing.
  * `trustProxy: true` or IP array whitelist: validates IPs via `net.isIP()` and extracts
    the verified client IP from the forwarding chain.
  * Standards-compliant headers: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`,
    and `Retry-After`. Emits HTTP 429 Too Many Requests with structured JSON error.

2. IMPLEMENTED COMPONENTS
--------------------------------------------------------------------------------
A. Storage Persistence Auditor (`packages/storage/src/persistence-audit.ts` & `index.ts`):
   - `isEphemeralPath(path)`: Heuristic & prefix detection for ephemeral filesystems.
   - `verifyStorageWritable(path)`: Probe-file read/write verification.
   - `auditStoragePersistence(path, deploymentModel, isProduction)`: Returns diagnostic
     status, warnings, and volume mount recommendations.

B. Pluggable Rate Limit Subsystem (`apps/api/src/rate-limiter.ts` & `middlewares.ts`):
   - `RateLimitStore` interface: Pluggable storage backend.
   - `MemoryRateLimitStore`: In-memory Map for standalone single-instance setups.
   - `FileBackedRateLimitStore`: Atomic file persistence surviving server restarts and
     coordinating local worker processes without Redis.
   - `RouteRateLimitRule`: Configurable path rules for isolated tier limits.
   - `calculateOperationCost(req)`: Query complexity weighting for expensive operations.

C. Search Provider Rate Limiting (`packages/ranking/src/providers/provider-rate-limiter.ts`):
   - `ProviderRateLimiter`: Sliding-window limiter tracking outbound provider requests.
   - `acquire(providerId)`: Proactive check returning retry-after cooldowns.

D. Trusted Proxy Resolution (`apps/api/src/router.ts` & `server.ts`):
   - `resolveClientIp()`: Validates proxy trust and sanitizes `X-Forwarded-For`.
   - `ApiServer`: Boot-time storage audit, `trustProxy` and `deploymentModel` options.

E. Hosting & Deployment Documentation (`docs/hosting-and-deployment.md`):
   - Complete guide covering standalone, clustered, and serverless hosting models,
     persistent volume Docker commands, proxy setups, and zero paid infrastructure.
